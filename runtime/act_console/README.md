# SO101 真实机械臂 ACT 自主启动项目

这个项目用于在本机独立启动已经训练好的 ACT，显示顶部和腕部画面、启动阶段与执行数据，不需要通过 Codex 对话启动。模型、Python、日志和缓存沿用 E 盘原有文件，不创建新环境，也不复制权重和数据集。

## 日常启动

1. 夹紧从臂，准备娃娃和盒子，清空运动范围。接好从臂供电和 USB、两路摄像头。关闭腾讯会议、系统相机、舵机调试软件、遥操和相机对齐网页的采集进程；这些程序不能与本程序同时占用设备。ACT 不需要主臂，可以只连接从臂。
2. 双击本目录的 `launch.cmd`，或在 VS Code 的“终端 → 运行任务”选择“ACT 打开自主启动界面 不自动运动”。打开界面不会连接硬件，点击“预检与预热”后才连接；这一阶段不改变力矩、不执行模型动作。如果原来已有力矩，机械臂仍保持原有状态。
3. 等待“就绪”，检查左侧是顶部、右侧是腕部真实画面，并确认腕部镜头无遮挡。画面身份必须由你核对，软件不能通过摄像头编号证明它是哪一台设备。
4. 如果力矩状态有 0，先可靠支撑机械臂，勾选确认，点击“当前位置保持”。程序把当前实测位置写成目标后再开启力矩，不追逐重启前留下的旧目标。确认机械臂已经保持后，移开手和支撑，重新勾选确认。
5. 确认夹爪为空、当前位置到标准起点的完整复位路线与抓放范围都无障碍，勾选三个确认项，点击“开始 ACT”。程序先按大臂到手腕递减的速度复位到保存的示范起点，再用新鲜图像和状态直接运行 ACT，不额外对齐模型首目标，也不运行主臂。界面默认和最高时限均为 17.5 秒；低速起点复位不占用这 17.5 秒。当前界面使用 `control_mode=standard` 简化模式。
6. 随时点击“停止模型动作”或按 Esc。程序停止下发模型动作，保留从臂力矩，保存日志。计时完成不是成功识别，也不会自动归位、重抓或释放力矩。你先观察并点击“成功”“失败”或“未判断”；只有失败且需要归因时，再要求分析录像。

软件停止依赖程序和串口响应，不代替硬件断电。窗口显示停止请求后若机械臂仍异常运动，应直接切断供电，不等待界面恢复。关闭窗口会请求正常停止，不能用强杀进程代替正常退出。释放力矩必须另行确认可靠支撑；当前界面没有自动释放按钮。

每次尝试结束后，先调整物体并核对复位路线，再准备下一轮；下一轮人工开始后自动执行起点复位。加权复位不是碰撞规划，不能从任意姿态盲目启动；若当前路径被盒子或娃娃挡住，应先清出安全路径。默认配置保留逐轮加载方式；启用 `resident_runtime` 后，同一窗口复用模型、处理器和双相机，只在首次或资源重新建立时预热。不要在旧线程尚未退出时启动第二个程序。

### 本次 39 条数据、10,000 步模型的测试配置

测试配置为 `E:/robot/experiments/act_real39_20261015_194416/real_test_settings.json`，不改默认旧模型路径。该配置启用常驻复用，复位速度为 `[8, 6.4, 4.8, 3.2, 1.6, 20]`（五个转动关节 °/秒，最后夹爪百分点/秒），即原复位速度整体两倍，ACT 控制频率与动作语义不变。

常驻模型仅在当前进程复用，不是网络模型服务。每轮仍按 USB 身份重新建立从臂串口会话，快速核对当前标定、位置、力矩、温度及报警，结束后断开串口而不卸力。双相机及模型保持加载，下一轮重新读取当前画面并清空策略、处理器与时间融合状态，不续发旧队列。每轮仍产生独立报告、轨迹和录像。设备故障、保持更新失败或配置变化不能盲目复用；重新准备时需再次完整检查和预热。

空闲时相机继续实时预览，舵机位置和温度栏是上轮最终反馈，不是持续监测。“释放模型与相机（不卸力）”或关闭窗口可释放这些资源，不向舵机发送卸力或运动命令；运行中先停止并等待保存。关闭窗口、显式释放资源、换权重/标定/相机配置后，下一次需要重新加载与预热。

## 启动流程和可见状态

```text
打开界面                    不访问硬件
    ↓ 点击预检与预热
按 USB 身份确定从臂串口      不依赖上次的 COM 编号
读取标定 边界 舵机状态       不修改标定 PID 或边界
加载本地 ACT 和处理器
打开两路原始 RGB 相机        同一进程独占相机
GPU 预热 20 次               不执行预热时的预测
    ↓ 清空策略队列和时间融合状态
就绪 等待人工确认            画面和状态持续显示
    ↓ 必要时手动请求当前位置保持
重新确认后点击开始
加权复位保存的示范起点        不倒放轨迹 不计入 ACT 时限
清空策略状态 重新读取输入     不额外移动到模型首目标
ACT 运行 最长 17.5 秒        100 步预测 每次执行当前 1 步 滚动融合
停止 保存 等待你的结果        不自动归位 不释放力矩
```

界面预览默认约 10 Hz，只用于显示；原始相机配置和控制目标都是 30 Hz。预览降频不会把模型输入降成 10 Hz。界面还显示累计实际下发频率、单步处理时长、图像到下发时的年龄、六个关节实测位置、边界裁剪次数、最高舵机温度和力矩状态。

显示的处理时长包括读位置、整理图像、预处理、推理和后处理，不是单独 GPU 前向耗时。实际频率可能低于 30 Hz，程序不会压缩间隔追赶漏掉的时刻。相机时间戳是主机接收时间，不代表硬件曝光同步。停止后两路图像会冻结在最后一帧，不能当作持续的实时监控。

预热只是消除部分首次调用开销，不是检验模型可靠性的证明。关节边界也不是碰撞检测。17.5 秒取自去手清洗版全部 10 条有效示范中最长的两个片段：episode 2、3 均有 525 帧，按 30 Hz 计算。裁剪片段保留放置、松爪及短暂稳定，不包含人工复位；这是最长有效示范时长，不是精确标记的成功瞬间。操作人确认娃娃已放入盒内、夹爪释放且娃娃没有掉出后按 Esc；否则到时或硬故障触发时停止。停止原因与任务结果分开记录，不自动识别成功。

简化模式只记录 150 ms 状态/预测时延、转动目标单步变化超过 5 度或夹爪超过 20 个百分点、首目标差超过 30 度/百分点，以及图像年龄超过 200/250 ms 的事件，不因这些诊断阈值中断或额外限幅。它仍使用官方相机的新帧可用性检查：采集失败、串口读取失败、非有限数据、非豁免舵机报警或力矩异常会停止。标定身份与目标边界仍需核对和裁剪。

当前 `gripper_overload_policy=log_gripper_only` 只豁免夹爪单独的 `Status=32`：其余五个关节状态必须均为 0。预检、复位、ACT 和温度复测期间都保留原始状态并记录 `gripper_overload`，不因这一项停止。夹爪 32 同时带有任何其他报警位，或其他关节出现任何报警，仍立即停止；力矩异常和温度规则也不变。此项只改变软件处理，不修改舵机限力、过载阈值或保护时间，不额外发送清报警或重启命令，也不把 32 当作抓取成功信号。固件仍可能降低夹持输出。

任一舵机读到不低于 60°C 时，先将当前位置写为保持目标，不继续发模型目标，每约 0.1 秒复测。连续约 1 秒仍存在高温就停止；连续两次温度均低于 60°C 才恢复。恢复时丢弃暂停前的预测、清空时间融合状态，再用新观测推理，不续发过期动作。温度暂停计入 17.5 秒任务预算，不自动延长；非豁免舵机报警或通信失败不等待温度复测。

标准起点保存于 `E:\robot\config\reference_start_pose.json`，来自规范示范，不是出厂零位，也不是 ACT 算法普遍要求的姿态。当前启动复位用于统一这轮测试条件。底座、肩部、肘部、腕部俯仰、腕部旋转分别以最高每秒 4、3.2、2.4、1.6、0.8 度单调靠近参考；空夹爪最高每秒 10 个百分点。起点复位仍检查转动关节 1 度、夹爪 3 个百分点的残差；不达标停止，不自动放宽。复位不改标定、PID 或边界，结束后也不自动释放力矩。

## 在 VS Code 中打开和运行

双击 `open_project.cmd`，会使用本机已安装的 `E:\software\vscode\Microsoft VS Code\Code.exe` 打开 `so101-real-act.code-workspace`。也可以在 VS Code 用“文件 → 打开文件夹”打开 `E:\robot\projects\so101_real_act`。

推荐使用“终端 → 运行任务”，而不是随意使用其他解释器的运行按钮。任务中固定使用 `E:\robot\envs\lerobot\python.exe -s -B`。`-s` 禁用 C 盘用户目录的 Python 包；这是必要的隔离设置，仅指定 E 盘解释器仍可能混入用户目录旧包。`-B` 不生成 Python 字节码缓存。启动器还把临时目录、Hugging Face、Torch 和 CUDA 缓存指向 E 盘，并关闭在线模型下载。

在项目终端中也可以直接运行：

```powershell
.\launch.cmd
.\launch.cmd --check
.\launch.cmd --plan
.\launch.cmd --simulate-ui
```

`--check` 只检查环境和文件，不打开相机或串口。`--plan` 只打印配置。`--simulate-ui` 显示合成图测试界面，完全不连接真机，也不是真实 ACT 评测。

Windows、显卡驱动和 VS Code 自身仍可能写少量系统日志或用户配置到 C 盘；项目不能保证系统零写入 C 盘。项目没有安装新软件到 C 盘，运行数据均保存到 E 盘。

## 配置和日志

默认使用从臂 USB 序列号 `SET_FOLLOWER_USB_SERIAL` 自动查找当前串口；COM 编号改变也会先核对身份。查到零个或多个匹配项就停止，不会随意选择另一个机械臂。主臂序列号 `SET_LEADER_USB_SERIAL` 不会被本项目控制。

相机默认顶部 0、腕部 1；重新插拔后编号可能改变。如果画面顺序错误，关闭会话后在 `settings.json` 修改 `top_camera` 和 `wrist_camera`，重新预检。不要为了显示方便调换模型输入名称。默认不打开笔记本相机。未经重新验证，不改变控制频率、chunk 或时间融合参数；当前加载器会拒绝这些控制合同变更。

每次会话保存到 `E:\robot\logs\self_service_act\日期时间 随机后缀\`：

| 文件 | 内容 |
| --- | --- |
| `report.json` | 软件结果、设备身份、首目标、边界裁剪、实际计时、最终反馈；`task_success` 默认空值 |
| `events.jsonl` | 启动、就绪、对齐、运行、停止等阶段事件 |
| `reference_reset.csv` | ACT 前的加权起点复位与到位验证，不属于模型执行轨迹 |
| `initial_alignment.csv` | 仅旧 `guarded` 模式产生；简化模式不再二次对齐模型目标 |
| `act_trial.csv` | 每步实测关节、原始与下发目标、目标变化量、输入到下发的时延、图像年龄及下发间隔 |
| `act_top.avi` 和 `act_wrist.avi` | 本次 ACT 执行阶段的两路 MJPG 视频，用于可选故障分析 |
| `initial_top.png` 和 `initial_wrist.png` | 开始前采用的真实画面 |
| `operator_result.json` | 你点击的成功、失败或未判断，独立于软件计时结果 |

预检失败或开始前停止时，执行阶段文件可能没有产生。视频标称 30 fps，严格时序以 CSV 的真实时间为准，不按视频帧数倒推控制耗时。原始记录不会自动删除；日志积累会占用 E 盘空间。

## 常见停止原因

画面打不开时，优先检查占用相机的软件与编号；不是反复安装驱动。串口失败时，先关闭舵机调试软件、遥操与其他控制进程，再检查 USB 身份。标定不匹配时不要自动覆盖，先核对是否重标定或连接错臂。简化模式会因实际采集/通信失败、非有限输入、非豁免舵机报警、力矩异常或确认持续高温停止；软诊断阈值及夹爪单独 32 的事件写入 `report.json` 的 `diagnostic_warnings`，原始状态保存在 `servo_health_records`。

共享核心的命令行默认仍为旧 `guarded` 模式，报警策略默认 `stop`，避免改变其他调用者。日常项目通过 `settings.json` 明确传入 `--control-mode standard --gripper-overload-policy log_gripper_only`。对比实验应区分夹爪豁免前后的运行合同，不能将调整前后结果当作完全相同的停止条件。

官方部署步骤与本机差别见 [官方部署与本机适配](docs/official_and_local.md)。
