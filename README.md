# SO101数采平台

SO101 Data Platform：面向 SO-ARM101 主从臂的 Windows 本地数采工作站。界面使用 Python + 系统 WebView2，底层调用 LeRobot 和仓库附带的适配器；不打包浏览器内核，不需要 Node 常驻服务。

## v0.3.0：可配置的工作区与设备

- 可从任意可写安装目录启动，不再要求 E 盘或原开发机器目录。
- 首次打开无需模型、标定或机械臂；默认硬件锁定，不自动连接和运动。
- 在配置页选择工作区、LeRobot Python、主从臂各自的 USB 身份和标定文件、Top/Wrist 相机。
- 任务起点、模型、解释器等只读输入可位于工作区外；数据/日志/回流等管理和写入路径限制在自己的工作区内。
- 各功能分别检查配置。采集不要求模型和固定起点；ACT/复位才要求对应资源。
- 仍严格核对 USB 身份、角色、标定和限位；不是通过删除保护适配其他设备。

**这是开发中的可配置源码版，不是经过多机型认证的安全控制器。新设备必须逐项验收。** 当前只适配 SO101 六个标准关节和 STS3215，不声称支持任意机械臂。

## 新用户启动

1. 安装 Python 3.12（含 Python Launcher）及系统 Microsoft Edge WebView2。
2. 下载/克隆仓库到自己的目录，双击 `setup-ui.cmd`，创建仓库内的 `.venv-ui` 并安装轻量 UI 依赖。该步骤不连接硬件，也不安装模型、CUDA 或机械臂驱动。
3. 双击 `launch.cmd` 打开独立窗口。无需先复制配置模板，空白配置也能打开。
4. 进入“配置与环境”，选择自己的工作区和 LeRobot 环境的 `python.exe`。若改变工作区/服务端口，保存后正常关闭并重开。
5. 绑定主从臂身份，分别选择自己的标定 JSON；核对相机角色。保存绑定需要确认，但不会连接设备。
6. 先检查环境，再逐项验收相机、只读监控、力矩、基本控制、同步和采集；不要直接从 ACT 推理开始。

详细步骤见 [新机器配置与边界](docs/PORTABILITY.md) 和 [安全说明](SAFETY.md)。Python/WebView2 未安装、选定环境缺包或设备被占用时仍可能报错，不代表这些系统依赖已被打包。

已有 UI 环境可通过环境变量 `SO101_UI_PYTHON` 指向其 `python.exe` / `pythonw.exe`，再使用 `launch.cmd`；已有 LeRobot 环境在界面选择即可。UI 环境与采集/推理环境可以不同，不要求固定解释器路径。

所有默认入口打开时均锁定硬件。解锁只改变操作授权，不连接设备；连接与执行仍是独立操作。

## 后端依赖

离线界面不需要 Torch；数据读取、采集和控制使用配置页指定的后端环境。点击“检查所选环境”只检查模块可发现性，不导入模型、不预热 GPU、不打开串口或相机。

本版依赖 LeRobot 的特定 API，建议参照 [后端环境说明](docs/PORTABILITY.md#后端环境) 配置已记录的版本与小补丁。`environment.observed.json` 是原开发机器的版本记录，不是对任意硬件保证兼容的安装锁。

## 功能

- 双相机预览可与从臂监控/基本控制同时使用；相机和串口分别管理。
- 单关节/多关节目标位置与插值速度控制、保持/释放力矩、停止与 Esc。
- 新建或补录数据集；首次缓慢同步后连续遥操；人工开始、录制/复位阶段、Space 提前结束、语言指令与场景描述。
- 双相机同步回看、多关节/传感器曲线、成功/失败审核、可恢复归档。
- 保留原始数据的裁剪：只裁剪成功条目；每条原轨迹保留一个有效裁剪，重裁替换；审核状态共享。
- ACT 启动前复位、人工启动、历史和数据回流；策略轨迹不会自动批准为专家数据。
- 前端/后台/窗口构建核对；源码变更后拒绝新运动，停止入口保留。

## 配置与数据存储

| 内容 | 位置与行为 |
| --- | --- |
| 工作区默认值 | 仓库目录下 `workspace/`，可在配置页改到其他盘/目录 |
| 用户配置 | 仓库的 `state/settings.json`；更改前备份至 `state/config_history/`，不提交 Git |
| 数据、日志、回流、缓存 | 工作区内各自独立子目录，不能重叠或用磁盘根目录 |
| 数据审核与注册 | 工作区 `platform_state/`，换工作区后不会混用旧注册信息 |
| 任务起点 | 可选择自己的 JSON，或依据自己的标定填写六关节目标另存至工作区 `config/start_poses/` |
| 设备与标定 | USB 身份保存在私人配置；标定只读，不自动写回舵机或重新标定 |

串口重插换号后，`auto` 按唯一 USB 序列号查找；显式填写 COM 号时仍核对身份。序列号为空、重复或角色不符时拒绝连接，不按第一个串口猜测。没有唯一 USB 序列号的适配器，目前不能通过此严格绑定流程，需要先解决设备识别。

换标定需要确认；旧软件限位及未替换的旧起点关联会清除，旧文件不删除。不会自动生成所谓“通用安全起点”，也不会把六关节全零当作复位姿态。

## 当前边界

- 当前 UVC 相机管线固定 640×480、30 Hz、MJPG，界面预览频率独立；其他相机配置尚需适配。
- 当前 ACT 适配仍为 100 步预测、逐步执行、时间融合 0.01，要求 CUDA，任务最长 17.5 秒。这个历史任务配置不是任意模型的通用设置。
- 自备模型还必须与自己的关节坐标、单位、相机键名和训练场景一致，不能只凭“同为 SO101”直接套用其他设备的权重。
- 新配置默认遇到夹爪报警 32 也停止；只有明确选择并验收后，才启用“夹爪单独 32 仅记录”。这不影响原机器已有运行版的策略。
- 复位/插值不检查自碰撞或环境障碍；软件停止不能替代物理急停。
- 电流/负载等为原始反馈，不是标定后的接触力或触觉。扩展采样和 ACT 回流的真实频率仍需在自己的硬件上验收。
- 尚未做全新 Windows 机器的完整安装与真机验收，也未适配 Linux/macOS。

## 检查与测试

标准库离线测试不需要机械臂、原数据、模型或 Torch：

```shell
python -s -B -m unittest discover -s tests -p "test_*.py"
python -s -B server.py --check --offline
python -B tools/check_snapshot.py
```

v0.3 迁移测试使用合成标定、伪串口和临时工作区。另做了隔离安装目录中的前端 DOM 检查：空配置启动、保存双臂绑定、无模型准备采集、新建首个起点、换工作区后阻止新任务。DOM 检查不等于真实浏览器视觉或硬件验收。

原 v0.2 本机测试源码保留在 `tests/legacy/` 供追溯，不属于当前默认测试套件；其原机器 102 项通过结果不能替代 v0.3 或新设备验收。

## 主要文件

`desktop.py` / `server.py` / `worker.py` 分别负责窗口、本地服务、设备任务；`dist/` 为界面；`common.py` 为配置和路径契约；`device_inventory.py` 为只读依赖/端口枚举；`runtime/shared_scripts/` 为随仓库的控制适配器；`dataset_*`、`crop_collection.py`、`review_store.py` 等负责数据管理。

旧独立 ACT 控制台不再作为公开版第二入口，ACT 统一从主平台使用。原开发机器的桌面入口、项目、数据和私人配置没有被本次公开版迁移修改。
