# SO101数采平台

SO101 Data Platform：面向 SO-ARM101 主从臂的本地数据采集工作站，统一相机预览、设备控制、遥操采集、数据审核裁剪、示范回放和 ACT 推理记录。

**当前状态：v0.2.3 本机定制开发快照，不是下载后可直接运行的通用安装包。**

界面采用 Python + 系统 WebView2 独立窗口，不打包完整浏览器；底层调用 LeRobot 与仓库附带的控制适配脚本。无需 Node 常驻前端服务。当前实现面向 Windows，其他操作系统没有完成适配与验收。

## 功能范围

- 设备与控制：双相机预览与从臂监控/基本控制可同时使用；关节目标、速度、单关节或多关节执行；保持/释放力矩、停止和 Esc。
- 采集：新建或补录已有数据集；画面检查；首次缓慢同步；录制与人工复位阶段；Space 提前结束当前阶段；逐条语言指令和场景描述。
- 数据集：双相机同步回看、关节和传感器曲线、人工成功/失败审核、目录归档/恢复。
- 裁剪：保留原始轨迹；成功条目才能裁剪；同一原始 episode 保留一条有效裁剪，重裁替换；原始版与裁剪版共享审核状态。
- ACT：启动前参考姿态复位、人工启动、策略运行历史和数据回流；策略结果不会自动当成专家示范。
- 部署一致性：前端、后台和原生窗口核对构建标识；源码更新后拒绝新运动，停止入口仍保留。

这些是已有代码的功能范围，不代表所有真机链路都已验收。

## 下载后能直接用吗？

目前不能。以下限制仍然存在：

1. 正式目录、Python 解释器、缓存与部分路径检查固定在 `E:/robot`。
2. `desktop.py` 会拒绝从非正式目录运行；`launch.cmd` 也没有做相对路径启动适配。
3. 主从臂身份是强校验。本公开快照已将原设备序列号替换为 `SET_LEADER_USB_SERIAL` / `SET_FOLLOWER_USB_SERIAL`，必须重新配置并验证自己的设备；不能删掉身份保护后直接运行。
4. 本机标定、任务起点和模型权重未上传。不能把别人的标定和起点当作本机通用配置。
5. 当前初始化仍会核查 ACT 权重、标定等路径，即便只想离线浏览，也可能因缺少这些文件失败。
6. 一些测试依赖原本机数据/日志 fixture，不是全新克隆后即可直接通过的测试套件。

详见 [迁移限制与后续事项](docs/PORTABILITY.md)。本次上传没有把上述限制包装成已经解决。

## 源码结构

| 目录或文件 | 用途 |
| --- | --- |
| `desktop.py`、`server.py`、`worker.py` | 原生窗口、本地服务、设备/任务进程 |
| `dist/`、`assets/` | 界面资源和图标 |
| `common.py`、`config.example.json` | 配置契约和脱敏模板；本机 `config.json` 不跟踪 |
| `dataset_*`、`cropping.py`、`crop_collection.py` | 数据集命名、审核、裁剪和归档 |
| `sensors.py`、`signal_tools.py`、`policy_capture.py` | 原始反馈、曲线和策略运行记录 |
| `runtime/shared_scripts/` | 平台依赖的自有控制/录制/ACT/复位适配代码快照 |
| `runtime/act_console/` | 既有 ACT 控制台适配代码；不是训练工程 |
| `runtime/patches/` | 本机 LeRobot 未提交修改及上游许可证 |
| `tests/test_*.py` | 原开发环境的离线回归测试源码 |
| `tools/check_snapshot.py` | 不导入设备模块的源码语法和发布内容检查 |
| `docs/LOCAL_WORKFLOW.md` | 原本机操作说明，仅作功能与流程参考 |
| `environment.observed.json` | 原机器的依赖版本记录，不是已验证的安装锁文件 |

`runtime/` 只是将原目录外的必要自有代码一并保留。当前配置不会自动定位这里，需要明确部署映射。旧数据清理、个人迁移和针对历史数据的执行脚本没有作为发布入口提供。

## 可安全执行的源码检查

在安装了 Python 3.12 的机器中，可在仓库目录执行：

```shell
python -B tools/check_snapshot.py
```

该检查只解析 Python/JSON，不导入控制模块，不枚举串口、不打开相机、不加载模型。它不代表硬件功能通过。

## 复现原开发布局前需完成的工作

这不是一键安装步骤，也不会自动安装驱动或启动设备：

1. 先阅读 [安全与设备配置约定](SAFETY.md) 和 [迁移限制](docs/PORTABILITY.md)。
2. 安装并核对系统 WebView2、UI 隔离环境与 LeRobot 隔离环境。参照版本记录核对依赖，不能把它当作保证兼容的安装命令。
3. 明确平台、`runtime/shared_scripts` 和 `runtime/act_console` 的部署目录，逐处核对目前的固定路径。
4. 从 `config.example.json` 创建自己的本机配置。完成自己的主从臂标定、设备身份绑定、相机角色核对，并提供自己的模型和任务起点。
5. 先完成配置/离线检查，再逐项验收只读连接、相机、保持/释放与受控小范围运动。不要直接从模型推理开始。

旧默认控制配置来自特定任务：30 Hz、动作块 100、逐步执行并时间融合、最长 17.5 秒。它不是通用推荐；换模型、任务或数据后应重新确认。扩展反馈是原始寄存器读数，电流/负载不等于已标定的触觉或接触力。
