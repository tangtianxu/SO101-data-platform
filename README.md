# SO101数采平台

SO101 Data Platform：面向 SO-ARM101 主从臂的 Windows 本地数采工作站。界面使用 Python + 系统 WebView2，底层调用 LeRobot 和仓库附带的适配器；不打包浏览器内核，不需要 Node 常驻服务。

## v0.3.11：轨迹批量可恢复删除

- 可从任意可写安装目录启动，不再要求 E 盘或原开发机器目录。
- 首次打开无需模型、标定或机械臂；默认硬件锁定，不自动连接和运动。
- 在配置页选择工作区、LeRobot Python、主从臂各自的 USB 身份和标定文件、Top/Wrist 相机。
- 任务起点、模型、解释器等只读输入可位于工作区外；数据/日志/回流等管理和写入路径限制在自己的工作区内。
- 各功能分别检查配置。采集不要求模型和固定起点；ACT/复位才要求对应资源。
- 仍严格核对 USB 身份、角色、标定和限位；不是通过删除保护适配其他设备。

**这是开发中的可配置源码版，不是经过多机型认证的安全控制器。新设备必须逐项验收。** 当前只适配 SO101 六个标准关节和 STS3215，不声称支持任意机械臂。

## 新用户启动

1. 安装 Python 3.12（含 Python Launcher）及系统 Microsoft Edge WebView2。
2. 下载/克隆仓库到自己的目录，双击 `setup-ui.cmd`，创建仓库内的 `.venv-ui` 并安装轻量 UI 依赖。该步骤不连接硬件，也不安装模型、CUDA 或机械臂驱动。
3. 双击 `launch.cmd` 打开独立窗口。无需先复制配置模板，空白配置也能打开。
4. 进入“配置与环境”，选择自己的工作区和 LeRobot 环境的 `python.exe`。若改变工作区/服务端口，保存后正常关闭并重开。
5. 绑定主从臂身份，分别选择自己的标定 JSON；核对相机角色。保存绑定需要确认，但不会连接设备。
6. 先检查环境，再逐项验收相机、只读监控、力矩、基本控制、同步和采集；不要直接从 ACT 推理开始。

详细步骤见 [新机器配置与边界](docs/PORTABILITY.md) 和 [安全说明](SAFETY.md)。Python/WebView2 未安装、选定环境缺包或设备被占用时仍可能报错，不代表这些系统依赖已被打包。

已有 UI 环境可通过环境变量 `SO101_UI_PYTHON` 指向其 `python.exe` / `pythonw.exe`，再使用 `launch.cmd`；已有 LeRobot 环境在界面选择即可。UI 环境与采集/推理环境可以不同，不要求固定解释器路径。

所有默认入口打开时均锁定硬件。解锁只改变操作授权，不连接设备；连接与执行仍是独立操作。

## 后端依赖

离线界面不需要 Torch；数据读取、采集和控制使用配置页指定的后端环境。点击“检查所选环境”只检查模块可发现性，不导入模型、不预热 GPU、不打开串口或相机。

本版依赖 LeRobot 的特定 API，建议参照 [后端环境说明](docs/PORTABILITY.md#后端环境) 配置已记录的版本与小补丁。`environment.observed.json` 是原开发机器的版本记录，不是对任意硬件保证兼容的安装锁。

## 功能

- 双相机预览可与从臂监控/基本控制同时使用；相机和串口分别管理。
- 设备页可直接准备主从跟随；正常释放原监控/基本控制与独立预览后交接，画面检查→一次低速同步→手动进入正式遥操，不创建数据集。
- 单关节/多关节目标位置与速度的滑条＋数字双向编辑；拖动只修改草稿并选中关节，点击执行才下发，不做实时拖动驱动。
- 点动、保持、目标执行、同步和采集/遥操开始以明确按钮为授权，不再重复弹窗。释放力矩、复位/ACT/真机回放、设备绑定、数据覆盖/删除仍保留确认。停止与 Esc 保留。
- 新建或补录数据集；首次缓慢同步后连续遥操；人工开始、语言指令与场景描述。录制与复位不限时：Space 保存本条，再按 Space 结束复位并开始下一条；最后一条保存后结束本批。Esc 仍请求整批停止。
- 支持暂停／继续和“处理已采数据”。暂停在帧边界结束当前阶段，保存非空中断片段并默认排除训练，不占完整示范计划条数，不拼接暂停前后数据；复位中暂停不进入下一条。暂停时停止跟随、保留相机预览和力矩，继续监测报警、通信和温度；长时间离开仍应先支撑并结束／释放力矩。
- 继续需要点击按钮，不因 Space 或关闭处理窗口自动恢复；先按原同步速率缓慢追平主臂，再进入复位阶段。处理窗口可备注、审核及可恢复删除本次计划中已保存的条目。删除为侧录标记，不重排索引或擦除正在写入的数据；恢复也可从数据集页完成。训练导出需按成功且未删除的审核记录过滤，直接用 LeRobot 读取原始目录不会自动过滤这些侧录标记。
- 可选指令分组：每组填写条数＋指令，重复指令合并到同一小组；全部留空则维持普通单组目录。每个小组保存完整的标准 LeRobot 数据集与扩展反馈，不把多任务文件强行混成单任务标签。
- 新建/补录统一在采集工作台；数据集页专注查看、审核、裁剪、名称分类与归档恢复，不重复提供新建采集计划。外部来源数据导入属于独立流程，本版未新增格式转换或在线下载入口。
- 双相机同步回看、多关节/传感器曲线、成功/失败审核、可恢复归档。
- 轨迹列表顶部常驻“全选”复选框、半选状态、已选数量与清空。搜索时选择当前筛选结果，取消只移除这些结果，保留同视图中隐藏条目的选择；上方全选按钮可跨搜索选择当前视图全部轨迹。切换正常／已删除／全部视图会清空勾选，避免跨视图误操作。选择本身不播放视频、不改标记、不触发采集或设备命令。
- 全选或勾选多条后，可点击“删除所选轨迹（可恢复）”，整批一次请求、一次原子落盘，不逐条确认；失败不提交部分状态。删除条目从正常列表进入已删除视图，保持原始／裁剪版同步，保留各条备注和删除前审核状态。可在已删除视图全选后批量恢复；重复操作不会覆盖恢复记录。原始文件不擦除、不重排索引、不释放磁盘空间，直接读取 LeRobot 原目录仍含全部轨迹，训练导出须按成功且未删除记录筛选。采集中需先暂停，裁剪或其他设备任务中禁止删除／恢复。
- 曲线旁可直接“播放选中片段”，从绿色区间起点播放到终点自动暂停。普通播放默认使用选中范围，暂停后续播不丢失范围；可切换“整条”，支持逐帧定位和倍速。两路视频分别使用各自的 episode 偏移，预览不写入裁剪数据。
- 数据集选择改为宽幅窗口，完整显示任务、场景、时间、条数、备注与路径，保留分类、搜索和时间倒序；筛选或取消不会关闭当前数据集。当前数据集上方直接提供“修改名称与资料”，可编辑显示指令、场景、来源、阶段、审核和备注。稳定 ID 与实际路径只读，原始 task/轨迹不重写；普通资料保存不重复弹确认，首次标为可训练仍需人工确认。
- 数据集按“原始 / 可训练 / 处理与其他 / 全部”筛选，可搜索任务、备注与名称。已人工标为可训练且已有元数据的集合优先归入可训练；其余未排除的 raw 归入原始，处理待审/排除/未分类归入其他。分类不改文件或审核标记。各列表按记录中的开始时间倒序，无记录则按计划时间/目录创建时间兜底；不按最近修改时间，也不再截断前 100 份。
- 保留原始数据的裁剪：只裁剪成功条目；每条原轨迹保留一个有效裁剪，重裁替换；审核状态共享。
- 轨迹列表支持勾选、全选、勾选筛选结果，批量标记成功／失败／排除／待审核；一次保存、保留各条备注，不逐条弹窗，也不自动批准数据集用于训练。
- 自动裁剪先只读分析已成功原始轨迹，再展示可勾选的建议区间。六关节分别按度／夹爪百分点阈值、持续运动时间、比较窗口与前后留白判断，可选只裁开头；任务中间停顿保留。全部静止、无效数值或时间戳不连续的条目跳过，无法仅凭静止判断任务完成或识别误录的复位动作。
- 批量片段仍由官方 LeRobot 工具逐条写入、合并和校验，再统一提交到同一来源的一个裁剪集。重剪只替换对应条目并保留可恢复旧版；取消或失败不部分覆盖原集合。原始数值不平滑，视频／动作／传感器同步裁剪；新视频编码 H.264，已有未修改视频无损拷贝。
- ACT 启动前复位、人工启动、历史和数据回流；策略轨迹不会自动批准为专家数据。
- 前端/后台/窗口构建核对；源码变更后拒绝新运动，停止入口保留。

## 配置与数据存储

### 指令分组采集

采集工作台移除逐条指令文本框，改为“按语言指令分组”。可添加/移除小组，填写每组数量和语言指令；总条数自动合计，相同指令（去除首尾空白后）合并数量。空指令行忽略，全部留空则沿用默认指令和本次条数，不新建小组目录。分组时采用各组指令，不要求额外填写默认指令。

取消此前试采遗留的每次 30 条上限。普通采集、补录、每组数量及分组合计统一允许正整数，例如 50、200、1000；前端、保存配置和后端准备使用一致规则。仅保留 JSON/JavaScript 安全整数的技术边界，避免数量精度丢失，不作为实际采集规模建议。默认仍为 5 条，不会因升级自动开始或增加正在进行的作业；Space、Esc、逐条保存与机械臂保护保持不变。长时间采集需留意磁盘余量、设备温度并安排休息。

```text
datasets/本次采集文件夹/
  .capture-groups.json
  g001_把娃娃放进盒子/   # 独立 meta / data / videos / extras
  g002_把布块放进盒子/   # 同上
```

总文件夹是容器，不是假装成一个 LeRobot 数据集。数据集页按总文件夹分层列出小组，审核、裁剪与训练读取的是具体小组；需跨组训练时再使用官方数据集合并流程，不直接把总文件夹当作训练 root。每帧/每条仍保存真实 `task` 标签，方便后续 VLA 使用；ACT 不因此自动获得语言条件。

整次作业只连接设备、完成首次同步一次。组内各条正常录制/复位；切组时先完成文件落盘并保持当前位置，再低速跟随并等待“开始第 N 组”。若切组期间移动了主臂，按开始后仍需按原有 3°/夹爪 5 个百分点容差追平才进入正式录制，不从旧目标跳转。Esc 在切组等待中同样有效；不重复弹确认框，退出仍保持既有力矩策略。该路径已做真实 LeRobot 写盘＋伪设备测试，未做真机分组验收。

补录可选择分组总文件夹，按指令写回已有小组或新增小组；也可只选一个小组，沿用该组固定指令。已有普通数据集仍按单组补录，不迁移、不改目录结构。小组指令作为小组身份固定，描述、备注、审核标记仍可编辑。

| 内容 | 位置与行为 |
| --- | --- |
| 工作区默认值 | 仓库目录下 `workspace/`，可在配置页改到其他盘/目录 |
| 用户配置 | 仓库的 `state/settings.json`；更改前备份至 `state/config_history/`，不提交 Git |
| 数据、日志、回流、缓存 | 工作区内各自独立子目录，不能重叠或用磁盘根目录 |
| 数据审核与注册 | 工作区 `platform_state/`，换工作区后不会混用旧注册信息 |
| 任务起点 | 可选择自己的 JSON，或依据自己的标定填写六关节目标另存至工作区 `config/start_poses/` |
| 设备与标定 | USB 身份保存在私人配置；标定只读，不自动写回舵机或重新标定 |

串口重插换号后，`auto` 按唯一 USB 序列号查找；显式填写 COM 号时仍核对身份。序列号为空、重复或角色不符时拒绝连接，不按第一个串口猜测。没有唯一 USB 序列号的适配器，目前不能通过此严格绑定流程，需要先解决设备识别。

换标定需要确认；旧软件限位及未替换的旧起点关联会清除，旧文件不删除。不会自动生成所谓“通用安全起点”，也不会把六关节全零当作复位姿态。

## 当前边界

- 当前 UVC 相机管线固定 640×480、30 Hz、MJPG，界面预览频率独立；其他相机配置尚需适配。
- 当前 ACT 适配仍为 100 步预测、逐步执行、时间融合 0.01，要求 CUDA，任务最长 17.5 秒。这个历史任务配置不是任意模型的通用设置。
- 自备模型还必须与自己的关节坐标、单位、相机键名和训练场景一致，不能只凭“同为 SO101”直接套用其他设备的权重。
- 新配置默认遇到夹爪报警 32 也停止；只有明确选择并验收后，才启用“夹爪单独 32 仅记录”。这不影响原机器已有运行版的策略。
- 复位/插值不检查自碰撞或环境障碍；软件停止不能替代物理急停。
- 电流/负载等为原始反馈，不是标定后的接触力或触觉。扩展采样和 ACT 回流的真实频率仍需在自己的硬件上验收。
- 尚未做全新 Windows 机器的完整安装与真机验收，也未适配 Linux/macOS。

## 检查与测试

标准库离线测试不需要机械臂、原数据、模型或 Torch：

```shell
python -s -B -m unittest discover -s tests -p "test_*.py"
python -s -B server.py --check --offline
python -B tools/check_snapshot.py
```

v0.3 迁移测试使用合成标定、伪串口和临时工作区。另做了隔离安装目录中的前端 DOM 检查：空配置启动、保存双臂绑定、无模型准备采集、新建首个起点、换工作区后阻止新任务。DOM 检查不等于真实浏览器视觉或硬件验收。

前端开发测试可另外安装开发依赖（不属于软件运行依赖）：`npm install --ignore-scripts`，然后 `npm test`。它使用 JSDOM 和伪 HTTP 检查滑条双向同步、拖动不下发、设备所有权交接、Esc 取消与必要确认；不启动 Python、相机、舵机或模型。

可用已配置的 LeRobot 后端环境运行 `python -s -B -m unittest discover -s tests -p "integration_capture_groups.py"`。该可选集成测试使用真实数据写盘和伪设备，验证单组、分组和切组中止；不打开串口或相机。`integration_motion_trim.py` 使用合成双视频和六关节数值，验证只读运动分析、批量裁剪、交错重剪和取消后的整集合保护，同样不访问硬件。

原 v0.2 本机测试源码保留在 `tests/legacy/` 供追溯，不属于当前默认测试套件；其原机器 102 项通过结果不能替代 v0.3 或新设备验收。

## 主要文件

`desktop.py` / `server.py` / `worker.py` 分别负责窗口、本地服务、设备任务；`dist/` 为界面；`common.py` 为配置和路径契约；`device_inventory.py` 为只读依赖/端口枚举；`runtime/shared_scripts/` 为随仓库的控制适配器；`dataset_*`、`crop_collection.py`、`review_store.py` 等负责数据管理。

旧独立 ACT 控制台不再作为公开版第二入口，ACT 统一从主平台使用。原开发机器的桌面入口、项目、数据和私人配置没有被本次公开版迁移修改。
